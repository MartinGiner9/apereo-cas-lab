# Apereo CAS Lab

> Community project. This repository is not affiliated with or endorsed by the Apereo Foundation.

A reproducible laboratory for learning, running and integrating a real [Apereo CAS](https://www.apereo.org/projects/cas) server with realistic authentication backends and client applications.

## Goals

This project is intended to become a practical SSO playground where a developer can:

- run a real Apereo CAS server;
- authenticate users against PostgreSQL;
- understand TGTs, service tickets, SSO and Single Logout;
- expose principal attributes and roles;
- register services explicitly;
- integrate real Spring Boot, Node.js and PHP/Symfony clients;
- progressively add LDAP, MFA, OIDC and SAML;
- keep the environment reproducible with Docker.

It is **not** a production-ready identity platform and must not be deployed publicly with the demo credentials or defaults included in the lab.

## Baseline

- Apereo CAS: `8.0.1.2`
- Java: `25`
- PostgreSQL: `17`
- Service registry: JSON
- Authentication: JDBC + BCrypt
- Container orchestration: Docker Compose

CAS `8.0.1.2` is intentionally pinned. Version upgrades should be explicit and reviewed instead of silently following snapshots or floating CAS versions.

## First bootstrap

Copy the local environment file:

```bash
cp .env.example .env
```

Start PostgreSQL:

```bash
docker compose up -d postgres
```

Generate the official CAS overlay for the pinned CAS version:

```bash
./scripts/bootstrap-cas.sh
```

On Windows PowerShell:

```powershell
./scripts/bootstrap-cas.ps1
```

The bootstrap scripts use the official CAS Initializr instead of maintaining a fork of `cas-overlay-template`.

> The CAS container itself is deliberately not wired into Compose in this first scaffold. The next milestone will make the complete CAS + PostgreSQL environment start with one command after validating the generated 8.0.x overlay and PostgreSQL driver/module combination.

## Demo database

The PostgreSQL initialization script creates a small identity model:

```text
cas_user
role
user_role
```

Demo passwords are stored as BCrypt hashes generated by PostgreSQL `pgcrypto`; plaintext passwords are never stored in the database.

The initial demo accounts are documented in `infrastructure/postgres/init.sql` and are **lab-only credentials**.

## Security principles

Even though this is a laboratory, examples should model sensible defaults:

- no plaintext passwords in the database;
- no real secrets committed to Git;
- demo credentials clearly marked;
- explicit service registration rather than `https://.*` catch-all rules;
- pinned CAS versions;
- TLS before exposing CAS outside localhost;
- least-privilege database users when the lab evolves beyond the initial bootstrap.

## Roadmap

The short version:

1. CAS + PostgreSQL + JDBC authentication.
2. First Spring Boot CAS client and real SSO flow.
3. Attributes, roles and Single Logout.
4. Node.js and Symfony clients.
5. OpenLDAP profile.
6. MFA/TOTP and login throttling.
7. OIDC/OAuth2.
8. SAML.

See [docs/roadmap.md](docs/roadmap.md) for details.
